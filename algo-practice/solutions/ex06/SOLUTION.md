# ex06 — K ร้านยอดฮิต (heap)

## แนวคิด: นับก่อน แล้วคัดเหลือ k

1. **นับ** ด้วย `map[string]int` O(n)
2. **คัด k อันดับแรก** จากร้านที่ไม่ซ้ำ m ร้าน มีสองทาง

| วิธี | เวลา | เหมาะเมื่อ |
|---|---|---|
| เรียงทุกร้านแล้วตัด k ตัวแรก | O(m log m) | k ใกล้ m หรืออยากได้โค้ดสั้น |
| **min-heap ขนาด k** | O(m log k) | k เล็กมากเทียบกับ m (เช่น 10 จาก 100,000) |

## ทำไมหา "มากสุด" ต้องใช้ **min**-heap

อุปมา: เวที**รอบชิง k ที่นั่ง** ที่นั่งบนสุดของ heap คือ**คนที่อ่อนที่สุดบนเวที**
ผู้ท้าชิงใหม่ขึ้นเวทีมา ถ้าเวทีเกิน k คน ให้ไล่คนอ่อนสุดลง ซึ่งอยู่บนสุดของ heap พอดี หยิบได้ใน O(log k)
จบแล้วบนเวทีเหลือ k คนที่เก่งสุด

ถ้าใช้ max-heap จะต้องเก็บทุกร้าน (ขนาด m) แล้ว pop k ครั้ง เปลืองหน่วยความจำกว่า

## `container/heap` ใน Go (จุดที่ติดบ่อย)

ต้องเขียน 5 method ให้ type ของเรา แล้วเรียกผ่าน **`heap.Push(h, x)` / `heap.Pop(h)`** เท่านั้น

```go
func (h minHeap) Len() int           { return len(h) }
func (h minHeap) Less(i, j int) bool { return worse(h[i], h[j]) }  // ตัวที่ "น้อย" ขึ้นบน
func (h minHeap) Swap(i, j int)      { h[i], h[j] = h[j], h[i] }
func (h *minHeap) Push(x any)        { *h = append(*h, x.(entry)) } // pointer receiver
func (h *minHeap) Pop() any          { /* เอาตัวท้ายออก */ }
```

| พลาด | ผล |
|---|---|
| เรียก `h.Push(x)` ตรงๆ แทน `heap.Push(h, x)` | ต่อท้าย slice เฉยๆ ไม่จัดลำดับ heap ผลผิด |
| `Push`/`Pop` ใช้ value receiver | `append` ไปลงสำเนา heap ไม่โต ผลผิดหรือ panic index out of range |
| ลืมเงื่อนไขชื่อตอนจำนวนเท่ากัน | ผลสุ่มตามลำดับวนของ map เทส "tie at the cut-off" พังบางรอบ |
| Pop ออกมาแล้วใส่ผลจากหน้าไปหลัง | ได้ลำดับกลับด้าน เพราะ min-heap คืนตัวแย่สุดก่อน |

## โค้ด

ดู `top.go`

## Complexity

- เวลา O(n + m log k), หน่วยความจำ O(m) สำหรับ map และ O(k) สำหรับ heap

## พูดในห้องสัมภาษณ์

> "นับด้วย map ก่อน แล้วรักษา min-heap ขนาด k ไว้ บนสุดของ heap คือตัวที่อ่อนที่สุดใน top k พอเกิน k ก็ pop ทิ้ง
> ได้ O(m log k) ดีกว่าเรียงทั้งหมดเมื่อ k เล็ก ถ้าจำนวนเท่ากันผมใช้ชื่อตัดสิน ผลจะได้ไม่สุ่มตามลำดับของ map"

## คำตอบคำถามต่อยอด

1. **เรียงทั้งหมดกับ heap:** ดูตารางด้านบน ในงานจริงถ้า m ไม่ใหญ่มาก เรียงทั้งหมดอ่านง่ายกว่าและพอ
2. **ทำไม min-heap:** ต้องการไล่ตัว**อ่อนสุด**ใน top k ออกให้เร็ว ตัวอ่อนสุดจึงต้องอยู่บนสุด
3. **ออเดอร์ไหลเข้ามาตลอด:** ใช้ Redis sorted set (`ZINCRBY` ตอนมีออเดอร์ แล้ว `ZREVRANGE 0 k-1` ตอนอ่าน) ถ้าต้องการ "ในชั่วโมงล่าสุด" แบ่งเป็น bucket รายนาทีแล้วรวม หรือถ้ายอมผิดเล็กน้อยใช้ Count-Min Sketch
4. **รวม top 10 จาก 20 เครื่อง:** **ไม่ถูก** ร้านที่ได้อันดับ 11 ในทุกเครื่อง อาจมียอดรวมเป็นอันดับ 1 แต่ไม่ติด top 10 ของเครื่องไหนเลย ต้องส่ง**ยอดนับทั้งหมด**มารวม (หรือใช้ threshold algorithm)
