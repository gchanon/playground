# ex02 — ช่วงยาวสุดที่ไม่มีร้านซ้ำ (sliding window)

## วิธีตรงๆ ก่อน

เริ่มจากทุกตำแหน่ง แล้วขยายไปทางขวาจนเจอซ้ำ = O(n × ความยาวช่วง) กรณีแย่สุดเกือบ O(n²)
(วัดแล้ว: กับ input ใหญ่ในเทสเกิน 2 วินาที)

## แนวคิด: หน้าต่างยืดหด

อุปมา: เอา**กรอบหน้าต่าง**วางบนรายการ ขอบขวาเลื่อนไปทีละช่องเสมอ
ถ้าร้านที่เพิ่งเข้ามา**มีอยู่แล้วในกรอบ** ให้เลื่อนขอบซ้ายไป**ถัดจากตัวเก่า**ทีเดียว ไม่ต้องค่อยๆ เลื่อนทีละช่อง

เก็บ `lastSeen[ร้าน] = index ล่าสุด` ไว้ ทำให้รู้ทันทีว่าต้องกระโดดไปที่ไหน

## กับดักสำคัญ: ตัวซ้ำที่อยู่**นอก**กรอบไปแล้ว

`a b b a`:

| right | id | lastSeen ก่อนหน้า | left | ช่วง | best |
|---|---|---|---|---|---|
| 0 | a | - | 0 | a | 1 |
| 1 | b | - | 0 | a b | 2 |
| 2 | b | 1 (≥ left) | **2** | b | 2 |
| 3 | a | 0 (**< left**) | 2 ไม่ขยับ | b a | 2 |

ถ้าไม่เช็ก `prev >= left` ขอบซ้ายจะ**ถอยกลับ**ไปที่ 1 แล้วได้คำตอบ 3 ซึ่งผิด เทส "old duplicate behind the window" มีไว้จับข้อนี้

## โค้ด

ดู `run.go`

## Complexity

- เวลา O(n): ขอบขวาเดินรอบเดียว ขอบซ้ายไม่เคยถอย
- หน่วยความจำ O(จำนวนร้านไม่ซ้ำ)

## พูดในห้องสัมภาษณ์

> "เป็นโจทย์ช่วงที่ติดกัน ผมใช้ sliding window: ขอบขวาเดินทีละช่อง เจอร้านซ้ำในหน้าต่างก็กระโดดขอบซ้ายไปถัดจากตัวเก่า
> ต้องระวังกรณีที่ตัวเก่าหลุดหน้าต่างไปแล้ว ขอบซ้ายห้ามถอย ได้ O(n)"

## คำตอบคำถามต่อยอด

1. **แต่ละร้านโผล่ได้ไม่เกิน k ครั้ง:** เปลี่ยนจาก `lastSeen` เป็น `count[ร้าน]` ในหน้าต่าง ขอบขวาเพิ่ม count ของร้านที่เข้ามา ถ้าร้านนั้นเกิน k ให้หดขอบซ้ายทีละช่อง (ลด count ของร้านที่หลุด) จนกลับมาไม่เกิน ยังเป็น O(n) เพราะแต่ละตัวเข้าและออกอย่างละครั้ง หรือถ้าอยากกระโดดทีเดียวแบบเดิม ให้เก็บ index ล่าสุด **k ตัว** ของแต่ละร้านแทนตัวเดียว แล้วกระโดดไปถัดจากตัวที่ k นับย้อนหลัง (ดูบันทึกท้าย README ของ ex02)
2. **ID เป็น a–z:** ใช้ `[26]int` แทน map เร็วกว่าเพราะไม่ต้อง hash และหน่วยความจำคงที่
3. **Stream:** เก็บแค่ `lastSeen` ของร้านที่ยังอยู่ในหน้าต่าง ร้านที่ index น้อยกว่า `left` ลบทิ้งได้ หน่วยความจำจึงขึ้นกับขนาดหน้าต่าง ไม่ได้โตตามความยาว stream
