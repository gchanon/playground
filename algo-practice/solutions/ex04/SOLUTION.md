# ex04 — อีกกี่วันเบี้ยจะแพงขึ้น (monotonic stack)

## วิธีตรงๆ ก่อน

แต่ละวัน มองไปข้างหน้าจนเจอวันที่แพงกว่า = O(n²) กรณีแย่สุดคือราคาลดลงเรื่อยๆ แล้วพุ่งวันสุดท้าย
(วัดแล้ว: เทส input ใหญ่ทำแบบนี้เกิน 2 วินาที)

## แนวคิด: แถวคนรอ ที่ใครเตี้ยกว่าคนใหม่ได้คำตอบทันที

อุปมา: แต่ละวันคือคนหนึ่งคน ส่วนสูง = ราคา ทุกคนอยากรู้ว่า "อีกกี่วันจะมีคนสูงกว่าเรามาถึง"
คนที่ยังไม่ได้คำตอบให้**ยืนต่อแถว** (stack)

วันใหม่มาถึง: คนท้ายแถวที่**เตี้ยกว่า**คนใหม่ ได้คำตอบแล้ว (วันนี้ − วันของเขา) ออกจากแถวได้ ทำซ้ำจนท้ายแถวไม่เตี้ยกว่า แล้วคนใหม่ต่อท้ายแถว

ผลคือแถวเรียงจาก**สูงไปเตี้ย**เสมอ (monotonic) จึงเรียก monotonic stack

## ไล่ `73 74 75 71 69 72 76 73`

| วัน | ราคา | ออกจากแถว (ได้คำตอบ) | แถวหลังจบ (index:ราคา) |
|---|---|---|---|
| 0 | 73 | - | 0:73 |
| 1 | 74 | 0 → 1 | 1:74 |
| 2 | 75 | 1 → 1 | 2:75 |
| 3 | 71 | - | 2:75, 3:71 |
| 4 | 69 | - | 2:75, 3:71, 4:69 |
| 5 | 72 | 4 → 1, 3 → 2 | 2:75, 5:72 |
| 6 | 76 | 5 → 1, 2 → 4 | 6:76 |
| 7 | 73 | - | 6:76, 7:73 |

คนที่เหลือในแถวตอนจบไม่มีวันแพงกว่า = 0 (`make` ให้ค่า 0 ไว้แล้ว)

## จุดที่คนพลาด

- ใช้ `<=` แทน `<` → วันราคาเท่ากันได้คำตอบผิด เทส "equal is not higher" จับข้อนี้
- เก็บ**ราคา**ในแถวแทน**index** → คำนวณระยะวันไม่ได้

## Complexity

- เวลา **O(n)** แม้มีลูปซ้อน เพราะแต่ละวันเข้าแถว 1 ครั้งและออก 1 ครั้ง รวมทั้งหมดไม่เกิน 2n ครั้ง (amortized)
- หน่วยความจำ O(n)

## พูดในห้องสัมภาษณ์

> "ผมเก็บวันที่ยังไม่เจอวันแพงกว่าไว้ใน stack ซึ่งราคาจะเรียงจากมากไปน้อยเสมอ พอวันใหม่แพงกว่าท้าย stack ก็ pop และตอบได้ทันที
> ดูเหมือนลูปซ้อน แต่ทุก index ถูก push และ pop อย่างละครั้ง เลยเป็น O(n)"

## คำตอบคำถามต่อยอด

1. **อีกกี่วันจะถูกลง:** กลับเครื่องหมายเป็น `>` แถวจะเรียงจากเตี้ยไปสูงแทน
2. **ทำไม O(n):** นับจากจำนวนครั้งที่ push และ pop ไม่ใช่นับจากรูปลูป แต่ละ index เข้าและออกอย่างมากหนึ่งครั้ง
3. **Stream:** ตอบวันนี้ทันทีไม่ได้ เพราะคำตอบอยู่ในอนาคต แต่ทุกครั้งที่วันใหม่มาถึง ตอบให้วันเก่าที่ค้างอยู่ได้ทันที เป็นการตอบแบบ "ทยอยตอบ"
