# ex01 — คูปองจับคู่สินค้าให้พอดีงบ (hash map)

**เวลา:** 15 นาที · **ระดับ:** easy (ข้อวอร์ม)

## โจทย์

ร้านค้ามีโปรโมชันว่า "ซื้อ **2 ชิ้น** ราคารวม **พอดี** งบ ได้ส่วนลดเพิ่ม"
ให้หาสินค้า 2 ชิ้น (คนละชิ้น) ที่ราคารวมกันเท่ากับ `budget` พอดี

```go
func PairForBudget(prices []int, budget int) (i, j int, ok bool)
```

- คืน index `i < j` ที่ `prices[i] + prices[j] == budget`
- ถ้ามีหลายคู่ คืนคู่ไหนก็ได้
- ถ้าไม่มีเลย คืน `ok = false`

## ตัวอย่าง

| prices | budget | ผลที่ถูก |
|---|---|---|
| `[120, 70, 250, 30]` | 100 | `(1, 3, true)` เพราะ 70 + 30 |
| `[50, 10, 50]` | 100 | `(0, 2, true)` ราคาซ้ำได้ แต่ต้องคนละชิ้น |
| `[50]` | 100 | `(_, _, false)` ชิ้นเดียวจับคู่กับตัวเองไม่ได้ |

## ข้อจำกัด

- `len(prices)` สูงสุด 200,000
- ราคาไม่ติดลบ
- **เป้า:** เร็วกว่า O(n²) เทสมี input ใหญ่ที่จับเวลา 2 วินาที

## รัน

```bash
go test ./ex01_pair_budget/
```

1. ถ้า `prices` เรียงมาแล้ว ทำโดยไม่ใช้ map ได้ไหม ใช้หน่วยความจำเท่าไหร่
2. ถ้าต้องคืน **ทุกคู่** ที่ไม่ซ้ำกัน ต้องเปลี่ยนอะไร
3. ถ้าข้อมูลใหญ่จนไม่พอใส่หน่วยความจำเครื่องเดียว จะทำยังไง

## บันทึกหลังทำ (13 ต.ค. 2026)

### โค้ดที่ทำผ่าน

```go
func PairForBudget(prices []int, budget int) (i, j int, ok bool) {
	seenMap := make(map[int]int)

	for i, priceData := range prices {
		rest := budget - priceData

		if indexSeen, ok := seenMap[rest]; ok {
			return indexSeen, i, true
		}
		seenMap[priceData] = i
	}

	return 0, 0, false
}
```

- **O(n) time, O(n) space** ผ่านเทสทั้งหมด รวม `-race` input ใหญ่ใช้ 0.02s จากเวลาที่ให้ 2s
- **ทำถูก:** ถามก่อนจด (เช็ก `seenMap[rest]` ก่อนใส่ `seenMap[priceData]`) ถ้าสลับกัน เคส `[50]` budget 100 จะจับคู่ 50 กับตัวเอง
- **ถ้าเจอใน code review:**
  - `for i, ...` และ `ok` ชื่อซ้ำกับ named return `(i, j int, ok bool)` เกิด shadowing ทำงานถูก แต่อ่านแล้วต้องหยุดคิด `govet` ที่เปิด `shadow` จะฟ้อง แก้ได้ด้วยการตั้งชื่อใหม่ เช่น `j`, `found`
  - ใส่ขนาดเริ่มต้น `make(map[int]int, len(prices))` map จะไม่ต้องขยายตัวกลางทาง

### คำถามต่อยอด 1: ถ้า `prices` เรียงมาแล้ว

**คำตอบรอบแรก (ยังไม่ใช่):** เก็บผลต่างไว้ใน array ใหม่ แล้ววนหาในนั้นทุกรอบ วิธีนี้ยังต้องใช้หน่วยความจำ O(n) เหมือน map และการวนหาทุกรอบทำให้เวลากลายเป็น O(n²) จึงแย่กว่าวิธีเดิม

**คำตอบที่ถูก: สองนิ้ว (two pointers)** นิ้วซ้ายอยู่ที่ราคาถูกสุด นิ้วขวาอยู่ที่ราคาแพงสุด
- ผลรวม**มากเกิน** → ขยับนิ้วขวาลง (หาตัวที่เล็กลง)
- ผลรวม**น้อยเกิน** → ขยับนิ้วซ้ายขึ้น (หาตัวที่ใหญ่ขึ้น)

```go
func PairSorted(sorted []int, budget int) (i, j int, ok bool) {
	l, r := 0, len(sorted)-1
	for l < r {
		switch sum := sorted[l] + sorted[r]; {
		case sum == budget:
			return l, r, true
		case sum > budget:
			r-- // มากเกิน → นิ้วขวาถอยมาหาตัวที่เล็กลง
		default:
			l++ // น้อยเกิน → นิ้วซ้ายเดินไปหาตัวที่ใหญ่ขึ้น
		}
	}
	return 0, 0, false
}
```

| | map | สองนิ้ว |
|---|---|---|
| time | O(n) | **O(n)** เท่ากัน นิ้วรวมกันขยับไม่เกิน n ครั้ง |
| space | O(n) | **O(1)** มีแค่ `l`, `r` |

ที่เคยสับสน: O(1) ตรงนี้หมายถึง**หน่วยความจำ** ไม่ใช่เวลา เวลายังเป็น O(n)

**ถ้าโดนถามว่าทำไมทิ้งนิ้วขวาได้โดยไม่พลาดคู่ที่ถูก:**
- ถ้า `ซ้าย + ขวา > budget` นิ้วขวาจับคู่กับตัวที่เล็กที่สุดที่ยังเหลือแล้วยังเกิน
- ตัวอื่นที่เหลือมีแต่ใหญ่กว่า บวกกับนิ้วขวาก็ยิ่งเกิน
- นิ้วขวาตัวนี้จึงไม่มีทางอยู่ในคู่ที่ถูก ทิ้งได้อย่างปลอดภัย

### คำถามต่อยอด 2: คืน**ทุกคู่**ที่ไม่ซ้ำกัน

**ถามให้ชัดก่อน (ทำแบบนี้ถูกแล้ว):** "ไม่ซ้ำ" หมายถึงคู่**ราคา** ไม่ใช่คู่ index

```
prices = [10, 90, 10, 90, 50, 50], budget = 100
คำตอบ = [(10, 90), (50, 50)]
```

`(10, 90)` เกิดได้ 4 แบบจาก index แต่นับเป็นคู่เดียว ถ้ามี 50 ตัวเดียว `(50, 50)` ไม่นับ

**คำตอบรอบแรก:** เปลี่ยน `return` ในโค้ดเดิมเป็นเก็บลง slice แต่ได้คู่ซ้ำ ไล่ด้วยมือจะเห็น

```
i=1  90 → เจอ 10 ใน map → เก็บ (10, 90)
i=3  90 → เจอ 10 ใน map → เก็บ (10, 90) อีก ❌ ซ้ำ
i=5  50 → เจอ 50 ใน map → เก็บ (50, 50)
```

key ของ map ไม่ซ้ำก็จริง แต่ราคาเดียวกันเดินผ่านหลายครั้ง แต่ละครั้งก็ไปเจอคู่เดิมใน map

**แก้:** เก็บคู่ที่เจอแล้วไว้ใน set อีกตัว ใช้ราคาที่น้อยกว่าของคู่เป็น key

```go
func AllPairs(prices []int, budget int) [][2]int {
	seen := make(map[int]bool)
	found := make(map[int]bool) // key = ราคาที่น้อยกว่าในคู่ที่เก็บไปแล้ว
	var out [][2]int
	for _, p := range prices {
		q := budget - p
		small := min(p, q)
		if seen[q] && !found[small] {
			found[small] = true
			out = append(out, [2]int{small, max(p, q)})
		}
		seen[p] = true
	}
	return out
}
```

ทดสอบแล้ว:

| input | ผล |
|---|---|
| `[10, 90, 10, 90, 50, 50]` | `[[10 90] [50 50]]` |
| `[50]` | `[]` |
| `[50, 50, 50]` | `[[50 50]]` |
| `[90, 10, 30, 70, 10]` | `[[10 90] [30 70]]` |

O(n) time, O(n) space อีกทางคือเรียงก่อนแล้วใช้สองนิ้ว พอเจอคู่ให้ขยับข้ามค่าที่ซ้ำทั้งสองฝั่ง ได้ O(n log n) time

**บทเรียน:** ได้วิธีแล้วให้ไล่ตัวอย่างที่ interviewer ให้มาด้วยมือก่อนบอกว่าเสร็จ ข้อนี้จะเจอปัญหาตั้งแต่ `i=3`

### คำถามต่อยอด 3: ข้อมูลใหญ่เกินหน่วยความจำเครื่องเดียว

**ถามให้ชัดก่อน (ทำแบบนี้ถูกแล้ว):**
- `prices` มี 10,000 ล้านรายการ (int64 ราว 80GB) อยู่ในไฟล์บน disk หรือ S3
- เครื่องมี RAM 16GB **`seenMap` ใส่ไม่พอ**
- อยากรู้แค่ว่ามีคู่ไหม และคู่ไหน

**คำตอบรอบแรก:** "sort ก่อนแล้วใช้สองนิ้ว" มาถูกทาง แต่ interviewer จะจี้ต่อทันทีว่า **80GB แต่ RAM 16GB จะ sort ยังไง** เพราะ `sort.Slice` ต้องโหลดทุกอย่างเข้าหน่วยความจำ

**คำตอบที่ครบ: external sort แล้วใช้สองนิ้วบนไฟล์**
1. อ่านทีละก้อนที่พอดี RAM (เช่น 10GB) แล้ว sort ในหน่วยความจำ เขียนลงไฟล์ ได้ประมาณ 8 ไฟล์ที่แต่ละไฟล์เรียงแล้ว
2. **merge** 8 ไฟล์เข้าด้วยกัน อ่านหัวของแต่ละไฟล์ใส่ **min-heap** แล้วหยิบตัวเล็กสุดออกทีละตัว (heap แบบเดียวกับ ex06)
3. ทำสองนิ้วบนไฟล์ที่เรียงแล้ว นิ้วซ้ายอ่านจากต้นไฟล์ไปข้างหน้า นิ้วขวาอ่านจากท้ายไฟล์ถอยหลัง ใช้ RAM แค่ buffer สองก้อน

**อีกทางที่ไม่ต้อง sort: แบ่งไฟล์ตาม hash**
- ให้ราคา `p` กับ `budget - p` ไปตกก้อนเดียวกันเสมอ โดยใช้ hash ของ `min(p, budget-p)`
- แต่ละก้อนเล็กพอใส่ map ได้ แล้วทำแบบโค้ดหลักทีละก้อน
- วิธีนี้แบ่งไปหลายเครื่องให้ทำพร้อมกันได้ด้วย
