# ex07 — cache ราคาเบี้ยประกันแบบ LRU (map + linked list)

**เวลา:** 30 นาที · **ระดับ:** medium (ถูกถามบ่อยมากในตำแหน่ง backend)

## โจทย์

การขอราคาเบี้ยจากพาร์ทเนอร์ช้าและเสียเงินทุกครั้ง จึงต้อง cache ราคาไว้ในหน่วยความจำ
แต่เก็บได้ไม่เกิน `capacity` key ถ้าเต็มแล้วมี key ใหม่เข้ามา ให้ไล่ key ที่**ถูกใช้ล่าสุดนานที่สุด**ออก (Least Recently Used)

```go
func New(capacity int) *Cache
func (c *Cache) Get(key string) (int, bool)
func (c *Cache) Put(key string, value int)
func (c *Cache) Len() int
```

- ทั้ง `Get` ที่เจอ และ `Put` นับว่าเป็นการ "ใช้" key นั้น
- `Put` key ที่มีอยู่แล้ว = แก้ค่า + นับเป็นการใช้ จำนวน key ไม่เพิ่ม
- `Get` ที่ไม่เจอ ห้ามเปลี่ยนอะไร
- **เป้า:** `Get` และ `Put` เป็น **O(1)**

## ตัวอย่าง

```
c := New(2)
c.Put("a", 1)
c.Put("b", 2)
c.Get("a")      // (1, true)  → a ใช้ล่าสุด, b เก่าสุด
c.Put("c", 3)   // เต็ม → ไล่ b
c.Get("b")      // (0, false)
```

## ข้อจำกัด

- capacity สูงสุด 50,000 และมีการเรียกรวม 500,000 ครั้ง
- เทสจับเวลา 3 วินาที วิธีที่ต้องไล่หา key เก่าสุดทุกครั้งที่เต็มจะช้าเกิน
- ไม่ต้องรองรับหลาย goroutine พร้อมกัน (ดูคำถามต่อยอดข้อ 1)

## รัน

```bash
go test ./ex07_lru_cache/
```

## คำถามต่อยอดที่ interviewer มักถาม

1. ถ้าต้องใช้จากหลาย goroutine จะล็อกยังไง ใช้ `sync.RWMutex` ให้ `Get` ถือ `RLock` ได้ไหม
2. ถ้าแต่ละราคาต้องหมดอายุใน 5 นาที (TTL) ต้องเพิ่มอะไร
3. ถ้ามี server 10 เครื่อง cache ในหน่วยความจำของแต่ละเครื่องมีปัญหาอะไร และเมื่อไหร่ควรย้ายไป Redis
4. ถ้า key เดียวกันถูกขอพร้อมกัน 1,000 request ตอนที่ cache ยังไม่มี จะเกิดอะไรกับพาร์ทเนอร์ และกันยังไง
